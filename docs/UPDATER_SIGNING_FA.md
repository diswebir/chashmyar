# راهنمای یک‌بارهٔ کلید به‌روزرسانی امضاشده

[شروع GitHub](GITHUB_QUICKSTART_FA.md) · [انتشار و آزمون ویندوز](RELEASE_GUIDE_FA.md) · [README](../README.md)

این کار برای مالک مخزن است. چشم‌یار به‌روزرسانی را از **`diswebir/chashmyar`** می‌گیرد؛ این آدرس در سورس ثابت است و updater توکن GitHub کاربر ندارد، پس مخزن و Release باید برای دانلود عمومی قابل دسترس باشند. گردش انتشار به کلید خصوصی نیاز دارد و بدون تنظیمات زیر عمداً متوقف می‌شود. **هیچ کلید تولیدی/واقعی همراه این بسته نیست و هیچ Secret یا Variable در مخزن شما توسط این بسته ثبت نشده است.**

> کلید خصوصی یا رمز آن را به چت، Issue، commit، فایل workflow، artifact یا شخص دیگر نفرستید. دسترسی نوشتن به `main` و Actions را محدود و تغییرات را بازبینی کنید؛ هر کدی که اجازهٔ اجرا با Secret داشته باشد، از نظر فنی می‌تواند آن را افشا کند. Secrets فقط در job ساخت انتشار از `main` استفاده می‌شوند، نه در CI مربوط به pull request.

## ۱. ساخت کلید، فقط یک بار

اگر همین حالا یک کلید معتبر دارید که در نسخه‌های دارای updater استفاده شده است، **کلید تازه نسازید**؛ نسخه‌های نصب‌شده فقط همان کلید عمومی قبلی را می‌شناسند. کلید و رمز را از پشتیبان امن خود بازیابی کنید.

برای ساخت نخستین کلید روی رایانهٔ مورد اعتماد، [Node.js](https://nodejs.org/) و `npx` لازم است. این مرحله **فایل اجرایی چشم‌یار را نمی‌سازد** و Rust یا ابزار C++ لازم ندارد. PowerShell را باز کنید و پوشه‌ای **بیرون از مخزن** انتخاب کنید:

```powershell
$dir = Join-Path $env:USERPROFILE ".chashmyar-signing"
New-Item -ItemType Directory -Force -Path $dir | Out-Null
npx.cmd --yes "@tauri-apps/cli@2.12.4" signer generate --write-keys (Join-Path $dir "updater.key")
```

هنگام درخواست، یک رمز قوی انتخاب و مطابق راهنمای ابزار تکرار کنید. به‌جای نوشتن رمز در خط فرمان، آن را در اعلان تعاملی وارد کنید. بدون `--force` اجرا کنید تا روی کلید قبلی نوشته نشود. دو فایل ساخته می‌شوند:

- `updater.key` — کلید **خصوصی**؛ محرمانه نگه دارید.
- `updater.key.pub` — کلید **عمومی**؛ بعداً داخل برنامه قرار می‌گیرد.

از کلید خصوصی و رمز آن یک نسخهٔ پشتیبان رمزگذاری‌شده و امن جدا از مخزن داشته باشید. Secret ذخیره‌شده در GitHub بعداً برای مشاهدهٔ مجدد نمایش داده نمی‌شود. از دست دادن هر یک از کلید خصوصی یا رمز باعث می‌شود نتوانید برای نسخه‌های فعلی به‌روزرسانی قابل‌اعتماد بسازید.

## ۲. ثبت در تنظیمات مخزن GitHub

در مخزن `diswebir/chashmyar` وارد **Settings → Secrets and variables → Actions** شوید. در تب **Secrets**، از **New repository secret** استفاده کنید:

| نام دقیق | مقدار |
|---|---|
| `TAURI_SIGNING_PRIVATE_KEY` | تمام محتوای فایل `updater.key`، نه مسیر فایل |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | رمز همان کلید؛ اگر کلید واقعاً بدون رمز ساخته شده، این Secret می‌تواند تعریف نشود |

برای کپی محتوای فایل خصوصی بدون چاپ آن در ترمینال می‌توانید از دستور زیر استفاده کنید، در صفحهٔ Secret بچسبانید و ذخیره کنید:

```powershell
Get-Content -Raw (Join-Path $dir "updater.key") | Set-Clipboard
```

سپس در همان صفحه وارد تب **Variables** شوید و **New repository variable** را انتخاب کنید:

| نام دقیق | مقدار |
|---|---|
| `CHASHMYAR_UPDATER_PUBLIC_KEY` | تمام محتوای فایل `updater.key.pub`، نه مسیر فایل |

```powershell
Get-Content -Raw (Join-Path $dir "updater.key.pub") | Set-Clipboard
```

بعد از ثبت، در صورت استفاده از clipboard آن را پاک کنید (`Set-Clipboard -Value ""`) و به سابقهٔ clipboard یا همگام‌سازی ابری آن هم توجه کنید. کلید خصوصی و رمز را در سورس قرار ندهید. کلید عمومی محرمانه نیست، اما باید متعلق به همان کلید خصوصی باشد و برای انتشارهای بعدی ثابت بماند.

این سه مقدار را در **repository** ثبت کنید، نه در Variables/Secrets مربوط به یک Environment دیگر که workflow به آن متصل نیست. اگر کلید گم، اشتباه یا جابه‌جا باشد، ساخت/صحت‌سنجی یا انتشار متوقف می‌شود؛ جزئیات را در Actions ببینید، اما محتوای Secret را در گزارش مشکل قرار ندهید.

## ۳. پس از تنظیم کلید

۱. سورس کامل، از جمله `.github` و فایل‌های lock، را طبق [شروع GitHub](GITHUB_QUICKSTART_FA.md) در مخزن موجود قرار دهید و به `main` push کنید. هر push موفق می‌تواند بدون تأیید جداگانه Release عمومی بسازد. پایهٔ این سورس `2.4.10` است: اگر بیشترین تگ پایدار `v2.4.9` باشد انتشار بعدی `v2.4.10` خواهد بود؛ تگ برابر یا بالاتر باعث انتخاب Patch بعد از بزرگ‌ترین تگ می‌شود، نه بازنویسی آن. همان کلید موجود را حفظ و [راهنمای آزمون ۲.۴.۱۰](../UPDATE_2.4.10_FA.md) را بخوانید.
۲. در **Actions → Automatic Windows release**، هر سه job را بررسی کنید. پس از موفقیت، Release باید نشان **Latest**، نصب‌کننده، پرتابل، دو فایل `.sig`، `latest.json`، `SHA256SUMS.txt`، `LICENSE` و `THIRD_PARTY_NOTICES.txt` داشته باشد. بررسی کنید نشانی `https://github.com/diswebir/chashmyar/releases/latest/download/latest.json` فایل همان Release را می‌دهد. Workflow هم امضای فایل‌ها و هم نسخهٔ داخل امضا را بررسی می‌کند؛ هشت دارایی با آرشیوهای سورس خود GitHub متفاوت‌اند.
۳. **ارتقای نخست از نسخه‌های بدون updater یا بدون کلید سازگار دستی است.** همهٔ نسخه‌های قبلی لزوماً این محدودیت را ندارند؛ ۲.۴.۹ امضاشده برای آزمون اعلان نسخهٔ بعدی مناسب است. از پوشهٔ داده پشتیبان بگیرید، برنامه را کاملاً ببندید و پس از انتشار نخستِ امضاشده، نصب‌کنندهٔ مورد اعتماد جدید را در محل نصب قبلی اجرا کنید یا فایل پرتابل جدید را به‌جای فایل بسته‌شدهٔ قبلی قرار دهید. تنظیمات و گزارش‌ها در پوشهٔ دادهٔ حساب ویندوز هستند، نه کنار EXE پرتابل.
۴. از آن نسخه به بعد، برنامه پس از شروع و هر ۶ ساعت بررسی می‌کند و نسخهٔ قابل‌اعتماد را خودکار دریافت و امضا و نسخهٔ آن را کنترل می‌کند. اعلان و بخش «درباره» آماده‌بودن را نشان می‌دهند. **نصب و راه‌اندازی مجدد فقط پس از تأیید صریح کاربر** است؛ تایمر جاری متوقف می‌شود. پرتابل به دسترسی نوشتن در پوشهٔ فایل و WebView2 نیاز دارد.
۵. برای آزمایش واقعی updater باید دست‌کم دو انتشار امضاشده با همان کلید داشته باشید: نسخهٔ نخست را دستی نصب/اجرا کنید و سپس بررسی و نصب نسخهٔ دوم را روی ویندوز برای هر دو نوع امتحان کنید. چک‌لیست [راهنمای انتشار](RELEASE_GUIDE_FA.md) شامل بازگشت از خطا، داده‌ها، اعلان و نمایشگرهاست. ساخت CI به‌تنهایی این رفتار را ثابت نمی‌کند.

امضای Tauri صحت به‌روزرسانی را با کلید توکار بررسی می‌کند؛ این امضا **گواهی ناشر Windows Authenticode نیست**. بدون گواهی جداگانه، Windows SmartScreen ممکن است هنوز هشدار دهد. مقایسهٔ SHA-256 با فهرست منتشرشده نیز به‌تنهایی هویت ناشر را ثابت نمی‌کند.

## ۴. تغییر یا گم‌شدن کلید

تعویض ناگهانی `CHASHMYAR_UPDATER_PUBLIC_KEY` یا تولید کلید خصوصی جدید، امکان به‌روزرسانی خودکار نسخه‌هایی را که کلید قدیمی دارند قطع می‌کند. اگر کلید یا رمز گم شد، ابتدا یک مسیر ارتقای دستیِ قابل‌اعتماد و اطلاع‌رسانی به کاربران برنامه‌ریزی کنید؛ این پروژه گردش خودکار چرخش کلید ندارد. اگر کلید لو رفت، Secret را غیرفعال کنید، دسترسی‌ها و تاریخچهٔ انتشار را بررسی کنید و انتشار جدید با کلید تازه را فقط با یک مسیر دستی مورد اعتماد به نسخه‌های قدیمی برسانید.
